How the attacker lands a shell on the victim

PHASE 1/6
Attacker arms a listener on their Linode cloud server (port 4444). It passively waits for any machine to call home.
Attacker visits the vulnerable website and pastes a reverse-shell payload into the innocent-looking "host" field.
The form is submitted. Behind the scenes, Node.js hands the whole string to /bin/sh, which parses the semicolon as a separator.
The shell spawns bash -i and opens a TCP socket to the attacker's IP. The victim's own machine initiates the outbound connection.
The cloud listener catches it. A live, interactive shell session now exists between the two machines.
The attacker types; the victim runs; output flies back. Meanwhile the website's HTTP response still just said "reachable" — the blindness never mattered.
